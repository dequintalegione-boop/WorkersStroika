# WorkersStroika — БригадаУчёт

## Локальный запуск на Windows

Приложение можно запускать полностью локально — без публикации на сайте и без подключения к облачному серверу. Данные приложения хранятся в локальном хранилище браузера на этом компьютере.

### Первый запуск

1. Установите Node.js 22 или новее.
2. Откройте папку проекта.
3. Дважды нажмите `start-local.bat`. Скрипт установит зависимости при необходимости, соберёт production-версию и откроет приложение.
4. Адрес локального приложения: **http://127.0.0.1:4173/**.

Окно терминала с локальным сервером должно оставаться открытым, пока вы пользуетесь приложением. Для остановки сервера нажмите `Ctrl+C` в этом окне.

Также можно запустить вручную из терминала VS Code Insiders:

```powershell
npm ci
npm run local
```

### Установка отдельного приложения

Сначала запустите локальную версию и откройте адрес `http://127.0.0.1:4173/` в Chrome или Edge. В меню браузера выберите установку страницы как приложения. После установки запускайте именно ярлык локального приложения.

Локальная версия отличается от установленного ранее сайта: адрес сайта и адрес `127.0.0.1` — разные источники. Данные между ними автоматически не переносятся. Перед переходом экспортируйте JSON-резервную копию в старом приложении и импортируйте её в локальном.

### Обновление приложения

В терминале из папки проекта выполните:

```powershell
git pull --ff-only origin main
npm ci
npm run local
```

Если локальный сервер уже работает, сначала остановите его сочетанием `Ctrl+C`. Затем выполните команды обновления и запустите локальную версию снова. Откройте приложение по адресу `http://127.0.0.1:4173/`.

### Важно о данных

- Локальная версия не синхронизирует данные с установленным веб-сайтом или другими компьютерами.
- Не очищайте данные сайта для адреса `127.0.0.1` в настройках браузера: там хранится база приложения.
- Регулярно создавайте JSON-резервную копию в разделе «Данные».
- Сборка и запуск не удаляют и не перезаписывают данные браузера.

### Обновление темы X-Analytics
Третья тема хранится под ключом `modern-dark`, но называется X-Analytics. При выборе она меняет не только палитру: ширину и структуру боковой панели, бренд-блок, верхнюю панель и карточки контента.
Service Worker обновлён до версии `brigade-tracker-v6`; статические файлы теперь загружаются по схеме network-first, чтобы установленное PWA не удерживало старые CSS/JS-бандлы.
После `git pull` остановите локальный сервер через `Ctrl+C`, снова запустите `npm run local` и откройте `http://127.0.0.1:4173/`. Не удаляйте локальные данные приложения.


## Безопасность и приватность данных

- **Где данные.** Рабочие записи сохраняются в локальном хранилище браузера под ключом brigade-tracker-storage. Приложение не использует облачную базу и не реализует автоматическую синхронизацию.
- **Сетевые запросы приложения.** Код приложения не отправляет ФИО, телефоны, адреса объектов, смены, зарплаты, выплаты, финансовые операции или резервные копии на внешние серверы. Внешние CDN, аналитика и телеметрия не подключаются.
- **Что хранит GitHub.** Репозиторий содержит исходный код и файлы проекта, а не локальную базу браузера. Правила .gitignore исключают типовые экспорты, резервные копии, локальные базы и файлы .env. Эти правила не мешают принудительно добавить файл через git add -f.
- **Резервные копии.** JSON-файлы содержат персональные и финансовые данные и не зашифрованы. Храните их отдельно от репозитория.
- **Шифрования localStorage пока нет.** Данные доступны скриптам того же источника и программам с доступом к профилю браузера.
- **Импорт JSON** ограничивает размер файла 20 МБ, проверяет структуру, опасные ключи, глубину вложенности и количество записей до изменения хранилища.
- **CSV-экспорт** нейтрализует строковые значения, которые могут быть интерпретированы табличным процессором как формулы. Числовые поля сохраняются числами.
- **Сервер разработки и локальный preview** привязаны к 127.0.0.1 и не предназначены для доступа из локальной сети.
- **Ограничения.** Локальное хранение не защищает от вредоносных расширений, XSS, заражённого компьютера или физического доступа к незаблокированному устройству.


### Проверка зависимостей

CI блокирует известные уязвимости в зависимостях, которые входят в приложение. Полный аудит также проверяет инструменты разработки. На дату последней проверки для picomatch опубликовано предупреждение GHSA-fc5q-39xc-vjpf, но исправленная версия пакета ещё не выпущена. Предупреждение проходит по цепочке picomatch → fdir/tinyglobby → Vite. Все четыре пакета должны оставаться только dev-зависимостями. CI допускает только эти четыре пакета при подтверждённой связи с указанным advisory и проверяет lock-файл. Любая другая уязвимость или перемещение этой цепочки в зависимости приложения приводит к ошибке проверки.


## Публикация через GitHub Pages

Сайт проекта публикуется через GitHub Actions из собранной папки `dist`, а не напрямую из исходного корня репозитория. Для проекта Vite это обязательно: исходный `src/main.tsx` должен быть преобразован в браузерные JS/CSS-файлы.

1. Откройте репозиторий → **Settings → Pages**.
2. В блоке **Build and deployment** установите **Source: GitHub Actions**.
3. После слияния настройки публикации запустите workflow **«Публикация GitHub Pages»** во вкладке Actions (или дождитесь автоматического запуска после push в `main`).
4. Откройте опубликованный сайт: https://dequintalegione-boop.github.io/WorkersStroika/.

Vite использует отдельный базовый путь `/WorkersStroika/` только при сборке GitHub Pages. Обычный локальный запуск по `http://127.0.0.1:4173/` продолжает собираться с корневым путём. Service Worker и PWA-манифест учитывают подпапку сайта.
